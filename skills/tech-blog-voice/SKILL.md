# 기술 블로그 문체 (Joonwoo)

기준 블로그: https://93jpark.tistory.com/

기술 블로그 글을 쓰거나 고칠 때 아래 규칙을 따른다. 내용(사실·수치·결론)은 바꾸지 않고 문체와 구성만 맞춘다.

## 어미와 시점

- 존댓말 평서문 `~했습니다 / ~입니다`로 쓴다. 1인칭 회고체.
  - 예: "처음으로 JPA를 활용해서 프로젝트를 진행했습니다."
- 결론은 확신만큼만 말한다.
  - 예: "~것 같습니다", "~이 가장 낫지 않을까 생각했습니다"

## 리듬

- 긴 설명 사이에 아주 짧은 문장을 끊어 넣는다.
  - 예: "그럼 이제 끝난 걸까요? / 아닙니다."
- 질문을 던지고 바로 답한다.
  - 예: "과연 실제로는 어떤 차이를 보일까요?"
- 명사로 끝나는 짧은 문장을 가끔 쓴다.
  - 예: "백문이 불여일타."
- 가벼운 장난은 아주 가끔만 쓴다.
  - 예: "~~피부~~코드로 느낄 수 있었습니다"

## 글의 흐름

1. 문제 상황
2. 직접 재현 (코드·로그·쿼리)
3. 원인 설명
4. 개선
5. 결과 수치
6. 회고

- 마지막은 배운 점을 일반 원칙으로 넓히고, 인용으로 맺기도 한다.
  - 예: "만능키는 없습니다"

## 구성 요소

- 섹션 제목은 가볍고 감탄형으로 짓는다.
  - 예: "문제의 파악!", "그 다음은?"
- 본문은 대부분 문단으로 쓰고, 목록은 요약할 때만 쓴다.
- 코드, 쿼리, 로그 같은 근거를 보여준다.
- 굵은 글씨는 핵심 수치에만 쓴다.
  - 예: "**128ms에서 53ms**"
- 이모지는 글 하나에 많아야 1개.

## 용어

- 약어는 처음 나올 때 풀네임을 먼저 쓰고 괄호에 약어를 붙인다. 이후에는 약어만 쓴다.
  - 예: "Service Level Objective(SLO)" → 이후 "SLO"

## 쓰지 않는 것

- 자기 코드를 스스로 깎아내리는 표현 ("부끄러운 코드다" 등)
- 말줄임표(`..`)나 `(?)`로 내는 구어체
- 독자를 끌어들이는 `~하도록 하자`, `~해보자` 식 진행 문장
- 글 끝의 다음 글 예고 ("다음에는 … 남겨보도록 하겠다")
- 반말 평서문 (`~했다 / ~이다`)
